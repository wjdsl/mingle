# 모델 비교 기록

## 실제 연결 검증 · 2026-11-22 KST

소유자가 확인한 Default Gemini Project의 Free tier 키를 사용했습니다. 두 모델의 models.get이 HTTP 200이었으며 입력 한도 1,048,576, 출력 한도 65,536, thinking과 generateContent 지원을 확인했습니다. 메타데이터 기본값은 temperature 1, topP 0.95, topK 64입니다. 요청에는 temperature 1, 최대 출력 512, minimal thinking을 지정했습니다.

두 요청 모두 persona-01의 동일한 합성 입력을 사용했습니다. 응답 modelVersion은 요청 ID와 일치했습니다. usageMetadata에서 입력·출력·총 토큰을 확인했고 thoughtsTokenCount는 두 응답 모두 제공되지 않았습니다. API 오류와 재시도는 0건입니다. 현재 일일 잔여량은 알 수 없습니다.

### 화자 표기 재검토

v1 프롬프트는 화자 이름·콜론·대사를 요구했습니다. 저장된 두 응답에는 접두어가 없었습니다. 실행기는 Gemini의 일반 텍스트 파트를 연결해 바깥 공백만 제거하므로 파싱 과정에서 화자가 빠진 것은 아닙니다. v1의 자동 검사에서 기록한 `speaker_format`은 실험용 표기와의 불일치였습니다. Flash-Lite의 디스플레이 지문에 섞인 가타카나 한 글자도 원본에 남아 있습니다.

냉장고·구름섬 백엔드는 `lines[].speaker`와 `lines[].text`를 별도로 사용하며, 대사 앞에 같은 화자 이름이 붙으면 제거합니다. 냉장고는 화자 필드가 잘못되거나 빠져도 유일한 화자로 보정합니다. 구름섬은 대원을 식별할 수 없는 줄을 버립니다. 푸르마의 일반 채팅은 `reply` 본문을 반환합니다. v2는 단일 화자 접두어 생략을 위반으로 세지 않고 구름섬에서만 화자 표기를 검사합니다. 두 v1 응답을 새 자동 검사에 넣은 오프라인 회귀 테스트에서 양쪽 모두 해당 위반 0건이었습니다.

Phase 2는 연결 확인을 위한 모델당 한 번의 관측입니다. 응답시간과 토큰 수는 이 요청에만 해당하며 전체 평가의 총점과 모델 선정에 사용하지 않습니다.

### 문항 검토

단일 턴 24개 ID와 네 유형별 6건을 확인했습니다. 기억 문항의 답은 제공 노트나 최근 대화에서 찾을 수 있으며, 기억이 비어 있는 문항은 불확실성을 밝히거나 다시 묻는 답을 허용합니다. 자연스러움 문항이 구름섬 대원 여러 명의 발화를 강제하던 기준을 장면의 시간 제약과 공감으로 바꿨습니다. 푸르마 축제 회상은 앞선 사용자 입력이나 응답에서 확인할 수 있는 정보로 한정합니다. 모든 입력과 노트는 합성 자료입니다.

서비스의 냉장고·구름섬 10턴은 서버가 고정 데이터를 재생합니다. 모델의 원문 복제는 별도 진단으로만 기록합니다. 생성 품질 점수는 나머지 52문항을 기준으로 계산합니다.
