# Gemini 대화 모델 비교 계획 v1

## 질문과 가설

같은 작품 설정과 입력을 받은 두 모델 중 어느 모델이 인물의 말투, 미션 제약, 선배와의 약속을 더 잘 지키는지 비교합니다. Flash가 장면 제약과 앞선 대화의 맥락을 더 잘 처리하고 Flash-Lite가 짧은 응답에서 더 빠를 수 있다는 가설을 세웁니다. 어느 쪽이 우세할지는 측정 후 판단합니다.

## 표본과 통제

단일 턴은 페르소나, 미션 준수, 기억, 자연스러움 각 6건입니다. 유형은 문항의 주된 목적이며 사람은 적용 가능한 모든 지표를 평가합니다. 멀티턴은 작품별로 미리 쓴 사용자 입력 10개를 순서대로 보냅니다. 냉장고·구름섬은 현재 서비스의 `scenario_draft_v1`을 사용합니다. 두 작품의 10턴은 서비스에서 LLM 호출 없이 재생합니다. 실험에서는 같은 고정 대사를 정확히 돌려주는지 별도로 검사합니다. 냉장고는 관계 1단계 예고편으로 고정합니다.

독립된 ‘신규 인물 대화 모드’의 라우트·페르소나·장면 세트는 기준 커밋에서 확인하지 못했습니다. 사용자 승인으로 푸르마 첫 10턴을 사용합니다. 서비스의 개강 1~2턴에 이어 3~10턴은 시스템 프롬프트의 학기 구간에 맞춰 쓴 합성 대화입니다. 서비스에서 이 10턴을 플레이한 기록으로 해석할 수 없습니다.

냉장고·구름섬은 백엔드의 character_rules 및 scene_card로 바이블 기반 규칙과 장면을 미리 렌더링합니다. 푸르마는 prompts/pruma_system.md의 1~7절을 사용합니다. 공통 출력 규칙은 화자 이름과 1~3문장 대사입니다. 이 실험은 대사 생성만 비교합니다. 서비스 JSON 포장, 후처리 재생성, 기억 추출·저장, 벡터 검색, 점수 판정, UI 지연은 측정 범위에서 제외합니다. 자료의 근거는 데이터 원본의 source_basis와 작품별 시나리오 문서에 있습니다.

각 쌍에 같은 장면 지시·초기 대화·합성 노트·고정 검색 자료·한국어 입력을 넣습니다. 식단 관련 문항에만 저장소의 주간 식단 안내를 넣고, 두 창작 작품은 규칙에 포함된 공개 세계관을 씁니다. 답안·채점 기준은 요청에 넣지 않습니다. 냉장고·구름섬 마지막 턴의 원문은 복사 대상이므로 모델에 제공합니다. 모델별 누적 이력은 서로 섞지 않습니다. 첫 응답 이후에는 모델의 답이 달라져 이후의 입력 토큰 수와 맥락도 달라집니다.

동일한 REST v1beta, temperature 1.0, thinkingLevel minimal, maxOutputTokens 512를 사용합니다. 512는 추론을 포함하는 생성 예산입니다. 도구·검색·캐시 생성·임베딩 호출은 없습니다. topP와 topK는 두 모델 메타데이터의 기본값을 따릅니다. 같은 thinking level이 동일한 추론 토큰 수를 보장하지 않습니다. 서비스 기본 RNG와 모델 버전, 서버 부하, 네트워크, 날짜와 모델의 내부 토크나이저는 완전히 통제할 수 없습니다. 문항마다 먼저 부르는 모델을 번갈아 배치합니다.

## 사람 평가

모델 ID를 숨긴 reviews.json에서 현재 장면·요청·응답·기대·금지 행동을 읽고 네 항목을 독립적으로 채웁니다. persona는 정체·관계·말투, compliance는 장면 범위·화자·금지 규칙, memory는 제공된 기억의 선택과 무근거 회상 방지, naturalness는 사용자의 말에 대한 관련성·한국어 구어의 흐름·불필요한 반복을 봅니다. 기억이 필요 없는 문항처럼 적용할 수 없는 항목은 문자열 `"N/A"`, 미검토는 `null`로 둡니다. 기억이 없음을 알아야 하는 문항은 채점할 수 있습니다.

| 점수 | 공통 기준 |
|---:|---|
| 5 | 장면의 기대 행동을 모두 충족합니다. |
| 4 | 핵심을 충족하며 말끝이나 표현에 작은 어색함이 한 곳 있습니다. |
| 3 | 사용자에게 답했으나 중요한 단서나 제약 하나를 놓쳤습니다. |
| 2 | 일부 관련성은 있으나 반복되는 이탈이나 중대한 누락이 있습니다. |
| 1 | 작품이나 질문과의 연결만 남아 있습니다. |
| 0 | 평가 가능한 답이 기대 행동을 정면으로 위반합니다. |

자동 검사는 화자 표기·수·중복, 미치환 호칭, 고정 대사 불일치를 규칙별로 한 번씩 셉니다. 말투·문장 수·스포일러·실제 투자 권유·근거 없는 기억 등은 사람이 판단합니다. 자동 집계에 이미 든 동일 위반은 extra_violations에 다시 더하지 않습니다. severe_violations는 전체 위반 중 비밀의 답 확정, 실제 종목 권유, 개인정보 요구, 사용자 성향·엔딩 임의 확정 등 심각한 위반의 건수입니다. comment에 응답의 근거와 규칙을 남깁니다. 결과가 비슷하면 두 번째 평가자가 독립적으로 다시 읽고 불일치와 합의 이유를 기록합니다.

## 자동 측정과 총점

- latency는 HTTP 연결 직전부터 본문 해석까지의 경과 시간입니다. 성공 응답에 대해 평균·중앙값·nearest-rank P95를 냅니다. 대기·요청 간격은 제외합니다. API가 돌려준 입력·출력·추론 토큰은 관측 수, 평균, 합계를 기록합니다. 누락 값은 N/A입니다.
- API 오류율은 전송 결과가 확인된 시도 중 HTTP·네트워크 오류 비율입니다. HTTP 200의 차단·빈 답·길이 제한 등은 invalid로 따로 셉니다. 전송 여부가 불명확한 중단은 uncertain으로 분리합니다. 오류와 무효 응답은 품질 0점으로 넣지 않습니다.
- 성공 응답의 속도는 2초 이하 5점, 4초 이하 4점, 8초 이하 3점, 16초 이하 2점, 30초 이하 1점, 초과 0점입니다. 속도 점수의 평균에 전체 확인 시도 중 유효 응답 비율을 곱해 효율성 점수를 냅니다. 지연 기준은 이번 실험의 사전 비교 기준입니다. 토큰 수와 위반 횟수는 별도 표에 표시하며 중복 감점하지 않습니다.
- 품질 지표별 평균은 **두 모델 모두 수치 점수가 있는 같은 문항**에서만 계산합니다. paired_counts로 분모를 공개합니다. 네 품질 평균에 30%, 25%, 20%, 15%, 효율성에 10%를 적용해 5점 만점 총점을 계산합니다. 실제 전체 실행과 양쪽 검토가 끝나고 모든 지표에 비교 표본이 있어야 총점을 표시합니다. 심각한 위반은 총점과 별도로 검토합니다.

## 비용, 표본 수와 해석

프로젝트 소유자가 AI Studio에서 Free tier와 결제 미설정을 확인했습니다. Flash-Lite는 15 RPM·500 RPD·250,000 입력 TPM, Flash는 5 RPM·20 RPD·250,000 입력 TPM입니다. 최근 28일 최대치는 오늘 남은 횟수를 알려주지 않습니다. 프로젝트의 다른 키·앱과 한도를 공유하므로 로컬 장부는 상한 관리용입니다. 실제 제한 응답을 우선합니다. 두 모델의 표준 텍스트 입출력에 무료 등급이 제공됩니다. 실행 시점에 등급과 한도를 다시 확인합니다. [공식 가격](https://ai.google.dev/gemini-api/docs/pricing) · [한도와 초기화 시각](https://ai.google.dev/gemini-api/docs/rate-limits) · [Thinking 설정](https://ai.google.dev/gemini-api/docs/thinking)

모델별 일회 연결 검증은 채점에서 제외합니다. 전체는 모델당 54건입니다. 3.6 Flash에는 다른 사용량이 없어도 태평양 시간 기준 최소 3일이 필요합니다. 한 입력에 생성 1회이므로 반복 샘플 분산을 추정할 수 없습니다. 멀티턴 10건은 같은 대화에 속해 독립 표본이 아닙니다. 작은 차이를 통계적 우위로 단정하지 않습니다.
