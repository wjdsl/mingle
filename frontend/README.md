# 푸르마 채팅 프로토타입

React + Vite + TypeScript + 일반 CSS. 설치 기준 Node.js 22.15.1 / npm 10.9.2.

```powershell
cd frontend
npm install
npm run dev
npm run build
npm test
```

## 구현 범위

- 개강 2턴: 선택지와 300자 자유 입력 → 사용자 메시지 → 지연된 Mock 응답 → 진행·감정 갱신.
- 모바일·데스크톱 모두 최대 430px의 동일한 세로형 한 열 화면.
- 전체 화면은 뷰포트 높이에 맞춘다. 시작·에피소드·유저노트·앨범·엔딩 카드에 수동 화면 스크롤 없이 접근하도록 이미지와 여백을 남는 높이에 맞춰 배치한다. 낮은 높이에서는 장식 문구·도장을 줄인다. 채팅 목록의 최신 메시지 자동 스크롤은 유지한다.
- 채팅 선택지와 입력 안내의 장식 화살표를 제거했다. 전송 버튼은 유지한다.
- 시작 화면(로고·제목·게임 시작) → 개강 에피소드 소개(큰 캐릭터·진입 버튼) → 채팅 순서다. 에피소드 소개는 대화 턴마다 반복하지 않는다.
- 채팅 상단에는 진행 바와 유저노트·엔딩 도감 아이콘만 두고, 남은 공간을 대화 목록이 채운다. 새 메시지·응답·화면 크기 변경 시 최신 메시지로 자동 스크롤한다. 수동 스크롤은 과거 대화 열람을 위해 유지한다.
- 코믹 미연시 UI: 큰 캐릭터 소개 영역을 채팅에 복구하지 않고 캐릭터 메시지 옆에 기존 감정 PNG를 배치한다. 메시지별 감정을 보존하고 최신 응답에서만 1회 리액션을 표시한다. `또각` 대사는 별도 코믹 말풍선 스타일을 사용한다. 선택지는 hover·focus·active·선택함 상태를 구분한다.
- `useViewportHeight`는 Visual Viewport 변경을 구독한다. 가용 높이가 560px 이하이면 선택지를 가로 묶음으로 표시하고 장식 라벨을 줄여 입력 공간을 확보한다. 실기기 키보드 동작을 검증 완료한 것은 아니다.
- 유저노트 아이콘은 빈 상태 화면으로, 엔딩 도감 아이콘은 졸업 앨범 화면으로 이동한다. 돌아오면 입력문·대화·진행을 유지한다. 실제 기억 추출·저장 및 엔딩 판정·획득은 구현하지 않았다.
- 도감은 종이 앨범·제본 고리·테이프 사진 카드 그리드로 표현한다. 내 앨범은 획득 0개·전체 잠금 상태다. 4칸은 배치 예시이며 최종 엔딩 개수가 아니다. 미획득 엔딩명·이미지·조건은 노출하지 않는다.
- `디자인 샘플` 모드에서는 획득 카드 예시 1개를 비교할 수 있다. 샘플 카드나 `엔딩 카드 디자인 미리보기`에서 졸업 기념 엔딩 카드(U06)를 확인할 수 있다. 실제 획득·저장은 발생하지 않는다. MD §6.2의 카드 구조와 §6.3의 졸업 앨범을 바탕으로 디자인했다.
- 샘플은 PM 기획서 v0.2 §6.1의 후보 `종강 생존 푸르마` 문구를 사용한다. 최종 엔딩 확정을 의미하지 않는다. 저장·공유는 후속 구현 대상이다.
- 빈 입력·한글 조합 Enter·중복 전송·오류 재시도·재시작 처리.
- 메모리 상태만 사용. 새로고침하면 초기화하며 입력·통계를 서버로 전송하지 않는다.
- 실제 LLM·서버·6구간 전체·스탯·엔딩 판정·도감 획득 저장·인증·영구 저장·운영용 안전 검출은 미구현.
- 프로젝트 전체 설계의 캐릭터 선택 화면은 후속 범위이며 이번에는 시작·에피소드 소개를 거쳐 푸르마와 대화한다.

## 대사와 에셋

첫 SOS·첫 선택지·기본 반응은 `docs/planning` 브랜치의 푸르마 기획서 v0.2 §3.2를 참조했다.

제공된 `Images/PRUMA/[PNG] 2024 YU Character-PRUMA/` 원본을 변경하지 않고 다음 파일을 복사했다.

## 실패 시연 및 검증

개발 URL에 `?mockError=once`를 붙이면 각 논리적 요청이 처음에 실패하고 재시도에서 성공한다.
이는 네트워크 오류가 아닌 Mock 오류다. 재시도 때 메시지·완료 턴이 한 번만 반영되는지 확인한다.
`npm test`는 입력 경계, 중복·오래된 응답, 실패 복구, 2턴 종료·초기화, 메시지별 감정 보존을 검사한다.

실기기 모바일 키보드·스크린리더 검증은 별도로 필요하다.

## 이후 API 연결

`ConversationClient.sendTurn(request, signal)`를 구현한 서버 클라이언트를 `useChat`에 주입한다.
현재 타입은 화면 내부 계약이며 팀의 실제 API 계약이 아니다. 서버 경로·필드 매핑·스트리밍·상태 검증은 협의 후 적용한다.
API 키를 브라우저 코드나 `VITE_*` 환경변수에 넣지 않는다.

## 3개 작품 플랫폼 (2026-11-08)

초기 진입은 MINGLE 홈이다. `#/project/puruma`, `#/project/fridge`, `#/project/cloud`로 작품 소개에 직접 진입한다.

- 푸르마: 캐릭터 확인·호칭 → 기존 캠퍼스 UI·2턴 Mock → 졸업 카드 샘플/앨범.
- 냉장고 회장님: 호칭 → 3개 코미디 에피소드 → 고정 Mock 엔딩.
- 구름섬: 5명 팀 소개·호칭 → 3개 협동 미션 → 나나 고정 샘플 카드. AI 성향 분석이 아니다.
- 공유는 네이티브 공유/링크 복사/수동 복사이며 작품 소개만 공유한다. 이미지 저장은 미구현이다.
- 모든 진행은 메모리에서만 관리하며 새로고침하면 초기화한다. 실제 AI·백엔드·통계는 연결하지 않았다.
- `?mockError=once#/project/fridge`와 `?mockError=once#/project/cloud`는 단계별 첫 요청 실패/재시도를 시연한다.
- `npm test`는 기존 reducer 5건과 신규 Mock 클라이언트 3건을 검사한다. `npm run build`는 TypeScript 검사와 Vite 프로덕션 빌드다. 별도 lint 명령은 없다.
- 신규 시각물은 CSS 콘셉트 아트다. 지정 폰트는 이름/폴백만 설정했고 파일은 미포함이다. 원본 푸르마 에셋은 유지했다.
- 팀 원격 검토/변경 파일/검증 한계는 `PLATFORM_REVIEW.md`와 루트 `FRONTEND_DESIGN.md` 구현 부록을 참조한다. 원격 main은 설계서를 `docs/`에 두지만 현재 작업 브랜치 경로는 루트다.

## 2026-11-09 UX 개선판

- 작품 소개 → 호칭 → 대화로 바로 진입한다. 푸르마의 중복 시작 버튼은 제거했다.
- 공통 헤더의 ‘시연 모드’에서 Mock 안내를 펼쳐 볼 수 있다.
- 브라우저 뒤로 가기는 작품 내부 단계도 이동한다. 같은 작품에서 이전 화면으로 돌아가도 대화는 메모리에 남으며, 시작 버튼으로 새 체험을 시작하면 초기화한다. 홈 이탈·새로고침 후 복원은 지원하지 않는다.
- 결과의 주요 행동은 ‘다른 작품 보기’이며 재체험·작품 링크 공유·푸르마 앨범 기능을 유지한다.
- 이전 버전은 루트 `.backups/mingle-before-ux-2026-11-09-005413.zip`에 있다. 별도 폴더로 압축 해제한 뒤 `frontend/`에서 `npm ci`로 의존성을 복원한다. 현재 폴더에 자동으로 덮어쓰지 않는다.
- 작업 기록은 `UX_REDESIGN_REVIEW.md`를 참조한다.
