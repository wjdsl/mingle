# MINGLE Figma 연동 및 1차 UX 진단

2026-11-11. 코드 변경 전 조사. Figma 원본 파일 비교는 수행하지 않음: 사용자가 과거 파일 대신 새 React 기준 파일을 요청함.

## 확인 범위

- 로컬 React 19/Vite/TypeScript/일반 CSS, hash 작품 라우팅과 History API 단계, 메모리 상태. Platform → Home/ProjectEntry/ChatIntro → ChatLayout 또는 기존 Puruma ChatScene → 결과. 새로고침 영구 복원 없음.
- AGENTS, 루트 FRONTEND_DESIGN, README/frontend README, main 통합 worktree의 docs/FRONTEND_DESIGN, SRS와 냉장고/구름섬 바이블, 관리자 인증 소스 참고. 통합 worktree는 이전 main 통합 당시 자료이며 이번에 원격 fetch는 하지 않았음.
- 390×844 브라우저에서 홈, 의견 모달, 냉장고 10턴/결과, 푸르마 채팅/유저노트, 구름섬 호칭·채팅 3미션/결과 확인. 홈 Figma 캡처는 새 탭 기본 크기 1280px이다.
- 푸르마 이번 결과 화면, 실제 공유 전송/OS 시트, 이미지 실패, 실기기 키보드, 모든 분기, 스크린리더, 관리자 실제 화면은 미확인.

## 연결 결과

Figma MCP whoami 성공. Design 파일 생성, 페이지/레이어 편집, React 페이지 캡처 및 스크린샷 도구 사용 가능. 파일 목록 검색 도구는 제공되지 않음.

새 파일: https://www.figma.com/design/v7cfdtUK2I3iHzSTpL0FNH

홈 원본 frame 2:2: 편집 가능한 TEXT 37개, FRAME 61개. 전체 화면을 단일 이미지로 붙인 결과가 아니다. 원본 홈은 00 페이지, 토큰/진단/리디자인은 별도 페이지로 준비했다. 준비 페이지는 아직 프레임이나 토큰이 완성된 상태가 아니다. 다른 화면은 브라우저 조사만 했으며 Figma에 모두 전송했다고 보고하지 않는다.

캡처 스크린샷 확인: 레이아웃/이미지는 옮겨졌으나 ✳ 기호가 녹색 컬러 이모지로 변환돼 원본과 차이가 있다. 임포트 결과가 픽셀 단위로 일치하거나 재사용 컴포넌트화됐다고 볼 수 없다. 해당 기호는 리디자인에서 벡터로 교체 검토한다.

캡처를 위한 임시 index.html 스크립트는 전송 후 원본 바이트로 복원했다. 앱 소스/AGENTS/기획서 변경, commit/push 없음. 새 분석 보고서만 생성했다. 기존 FRONTEND_DESIGN의 미커밋 변경과 Images는 유지했다.

## 디자인 시스템 진단

--m-* 공통과 --w-* 테마 분리는 유지할 가치가 있다. 하지만 legacy tokens.css/chat.css, platform.css의 추후 덮어쓰기, puruma-refinements가 함께 적용된다. 카드/결과/연출의 동일 선택자가 반복되며 이전 규칙이 남아 있다. 현재 전체 색 대비 통과를 주장할 근거는 없다.

폰트 토큰은 Pretendard/Space Grotesk/Black Han Sans/Jua를 지정하나 배포 폰트 파일은 확인되지 않아 실제 환경별 폴백 차이를 해결해야 한다. 선언된 이름만으로 해당 폰트가 렌더링됐다고 판단하지 않는다.

제안 토큰: 공통 배경 #FAFAF8/표면 white/본문 #242424/경계 #E9E9E7/포인트 #7765A8·#E9E2FF 유지. 본문 15~16, 메타 11~12, 섹션 20~24, Hero 32~56. 간격 4/8/12/16/24/32/48. 반경은 입력/버블/카드를 각각 의미 이름으로 구분. 버튼 primary/secondary/quiet, 카드 project/coming/result, 버블 character/user/system/image. 실제 토큰 수치는 Figma 검토 후 확정한다.

반응형은 현재 600/1024 분기와 채팅 390 상한을 기준으로 유지 검토한다. 360/390/768/1440에서 새 디자인을 재검토해야 하며 이번 전체 화면 QA 완료를 뜻하지 않는다. 모션은 입장/메시지/장면/엔딩 역할로 토큰화하고 reduced-motion은 효과를 줄이되 필요한 정보와 순서는 유지한다.

## 우선순위와 Figma 워크플로

1. 채팅 390×844 공통 구조/첫 장면/선택지/고정 입력을 세 테마 나란히 재설계.
2. 냉장고 결과 카드와 하단 행동, 홈 썸네일/카드 정리.
3. 소개/호칭/피드백, 이후 관리자 요구사항 확정.

00 현재 캡처 → 01 토큰/컴포넌트 → 02 진단/결정 → 03 검토안으로 분리한다. 현재 캡처는 비교 기준으로 보존하고 리디자인은 별도 프레임에서 작성한다. 이후 승인된 프레임 node-id의 디자인 컨텍스트/변수/스크린샷을 읽어 기존 React 컴포넌트에 수동 반영한다. 실제 브라우저 같은 크기에서 비교하고 차이/제약을 기록한다. Figma 변경이 React로 자동 배포되거나 양방향 자동 동기화되는 기능은 구성하지 않았다.

현재 Figma Variables/공통 컴포넌트는 아직 만들지 않았다. Code Connect 역시 미설정이다. 다음 단계에서 기존 코드의 의미 토큰을 Figma Variables와 대응시키고 확정된 선택자만 정리한다. 디자인 방향 합의 전 코드 리디자인은 수행하지 않는다.


## 추가 조건 반영: 화면 유형별 레이아웃 제약

사용자 확정 방향: 메인은 웹사이트, 채팅은 모바일 비주얼 노벨, 관리자는 넓은 대시보드. 데스크톱 채팅 폭 확장/기기 목업 테두리는 도입하지 않는다.

Figma의 03 리디자인 검토안 페이지에 아래 편집 가능한 레이아웃 연구 프레임을 추가했다. 최종 비주얼/원화 적용/토큰 라이브러리 완료본이 아니다. 이미지 영역은 위치와 크기 검토용 placeholder다.

| 프레임 | ID | 크기 | 내부 구조 |
|---|---|---|---|
| Mingle Main / Desktop | 9:2 | 1440×900 | 넓은 콘텐츠 및 작품 카드 |
| Mingle Main / Mobile | 9:19 | 390×844 | 세로 카드 흐름 |
| Chat / Desktop Presentation | 9:36 | 1440×900 | 중앙 x=525, 390×900 채팅 |
| Chat / Mobile | 9:56 | 390×844 | 390 상한·가변 폭 채팅 |
| Ending / Desktop Presentation | 9:76 | 1440×900 | 중앙 390폭, 결과 내용/하단 행동 분리 제안 |
| Admin Dashboard / Desktop | 9:89 | 1440×900 | 사이드바/넓은 본문, 실제 통계 없는 빈 상태 |

React 브라우저 실측: 1440×900에서 프레임 x525/폭390/높이900, 헤더49/진행79.3/메시지562.7/입력209px. 390×844에서는 폭390/메시지506.7px. 360×844에서는 폭360/메시지506.7px. 세 크기 모두 가로 넘침 없음. Figma 채팅 구획 높이는 이 수치로 보정했고, 메시지 영역은 FILL/세로 스크롤로 지정했다. 도입/블러 오버레이는 채팅 뷰포트 내부의 숨김 레이어로 경계를 정의했다. 모든 연출 프레임/프로토타입이 완성됐다는 뜻은 아니다.

React의 낮은 높이(600 이하) 규칙은 composer에도 스크롤을 허용하므로, ‘메시지 목록만 스크롤’ 조건과 예외가 있다. 후속 구현 단계에서 키보드/가용 높이를 검토해야 한다. 엔딩은 현재 카드 아래 행동 영역이 밀리므로 Figma안의 고정 행동 영역은 의도적인 개선안이며 아직 코드와 일치하지 않는다.

Figma 서체에는 Pretendard가 확인되지 않아 레이아웃 연구는 확인된 Noto Sans KR을 사용했다. 최종 서체 동기화는 별도 작업이다. 연결된 기존 라이브러리와 Code Connect는 없음을 확인했으며 관련 없는 OS UI 키트는 추가하지 않았다. 코드/스토리/에셋/AGENTS는 수정하지 않았고 commit/push도 없다.
