# MINGLE UX 개선안 · 단계별 검토

작성일: 2026-11-09

상태: **1단계 검토안 · 사용자 확인 전 / 코드 미반영**

이 문서는 기존 팀 기획과 FRONTEND_DESIGN.md를 대체하지 않는다. 현재 Mock 프로토타입의 화면 구조와 문구를 개선하기 위한 제안이다. 실제 AI·분석·판정·저장 기능을 새로 구현하거나 구현된 것으로 표시하지 않는다.

## 1. 진행 순서와 확인 지점

| 단계 | 산출물 | 사용자 확인 시점 |
|---|---|---|
| 1. 화면 구조·문구 | 이 문서의 흐름·핵심 정보·버튼·고지 기준 | 코드 수정 전 |
| 2. 작은 코드 수정 | 진행 표시 불일치, 완료 버튼 간격, 승인된 중복 문구 정리 | 로컬 화면과 변경 내역 검토 후 |
| 3. 공통 UX 구조 | 헤더·버튼·진행·입력·결과 행동 영역 규칙, 컴포넌트 분리 | 대표 화면과 회귀 검증 후 |
| 4. 화면별 레이아웃 | 모바일 우선 홈·시작·채팅·결과. 공간 배분은 Figma 설계에서 먼저 합의 | 홈 → 채팅 → 결과 묶음별 검토 후 |
| 5. 통합 검증 | 세 작품 회귀 검사와 반응형·접근성 확인 | 완료 보고 |

각 단계의 확인을 받은 뒤 다음 단계로 진행한다. 현재는 1단계만 작성했다. Figma 파일 작성·코드 변경·테스트·배포는 이번 단계에서 수행하지 않았다.

## 2. 공통 흐름 제안

홈 → 작품 소개 → 캐릭터/팀 확인 및 호칭 → 첫 장면·채팅 → 결과 예시

- 작품 선택 후 대화까지 주요 버튼은 2회: 소개의 ‘체험 준비하기’, 호칭의 작품별 시작 버튼.
- 푸르마의 기존 시작 표지는 작품 소개와 통합한다. 에피소드 제목·상황·원화는 첫 장면에 재사용하고 별도의 세 번째·네 번째 시작 버튼은 없앤다. 기능 삭제가 아니라 진입 단계 통합이다.
- 푸르마 단일 캐릭터와 구름섬 5명의 이름·역할은 유지한다. 캐릭터 선택이 실제로 없는 상태에서 선택 기능처럼 표시하지 않는다.
- 작품 안의 ‘뒤로’는 이전 단계, MINGLE 로고는 홈으로 구분하는 방향으로 후속 설계한다. 저장이 없는 현재 상태에서 홈 복귀 시 진행 초기화 여부를 행동 전에 알린다. 구체적인 복귀 UI는 3단계에서 검토한다.
- 작품 테마·이야기·Mock 응답·호칭·선택지·자유 입력·리액션·유저노트·앨범·재시도·공유·재도전은 보존한다.

## 3. 화면별 핵심 정보와 문구

### 홈: 작품을 발견하고 선택한다

- 제목: **이야기 속으로, 당신의 차례.**
- 설명: **캐릭터와 대화하며 세 가지 세계를 만나 보세요.**
- 작품 목록 제목: **지금 만날 이야기**
- 각 카드 순서: 작품명 → 포스터 → 장르·한 줄 소개 → ‘작품 보기’.
- 포스터와 카드 밖에 같은 소개 문구를 반복하지 않는다. 영어 부제·VOL·장식 스티커는 일부만 남긴다.
- 모바일에서는 첫 작품명과 포스터, 다음 작품의 존재를 더 빨리 발견하도록 Hero와 카드 높이를 설계한다. 세 작품을 억지로 한 화면에 모두 넣지는 않는다.
- Coming Next는 작품 목록 뒤의 짧은 안내로 유지한다.

| 작품 | 홈 카드용 한 줄 소개 |
|---|---|
| 푸르마와 학교 다니기 | 길을 잃은 신입생 푸르마의 선배가 되어 주세요. |
| 우리 집 냉장고가 재벌 회장님이다 | 중고 냉장고 속 회장님과 수상한 동거를 시작해요. |
| 구름섬 구조대 | 다섯 대원과 힘을 모아 흔들리는 하늘섬을 구해요. |

### 작품 소개: 어떤 역할로 무엇을 경험하는지 이해한다

순서: 작품명 → 대표 아트 → 한두 문장 소개 → 역할·체험 분량 → 주요 버튼.

| 작품 | 역할·체험 정보 | 주요 버튼 |
|---|---|---|
| 푸르마 | 푸르마를 돕는 선배 · 개강 2턴 체험 | 체험 준비하기 |
| 냉장고 회장님 | 회장님과 동거하는 취업 준비생 · 3장면 체험 | 체험 준비하기 |
| 구름섬 | 구조대의 새 대원 · 3개 미션 체험 | 체험 준비하기 |

‘A형/B형’은 내부 분류로 남기고 사용자 화면에서는 역할 설명으로 대체한다. 재생 시간은 측정 전 임의로 표시하지 않는다. 작품의 정식 제목은 유지한다.

### 캐릭터·호칭: 함께할 인물을 확인하고 시작한다

- 제목/입력 라벨: **어떻게 불러 드릴까요?**
- 도움말: **별명으로도 좋아요. 비워 두면 ‘선배/입주민/새 대원’로 시작해요.**
- 12자 제한은 입력 옆 보조 정보로 표현한다.
- 푸르마: 원화와 이름·‘신입생’ 역할. 단일 캐릭터 확인임을 명확히 한다.
- 냉장고: 회장 이름과 ‘권위는 만렙, 잔고는 0원’ 한 줄 소개.
- 구름섬: 5명 이름과 짧은 역할은 기본 노출하고 긴 설명은 펼쳐 보기로 검토한다. 긴 5장 카드 목록이 호칭 입력을 밀지 않도록 배치한다.

| 작품 | 시작 버튼 |
|---|---|
| 푸르마 | 푸르마 만나기 |
| 냉장고 회장님 | 회장님 만나기 |
| 구름섬 | 구조대 합류하기 |

### 채팅: 현재 장면을 이해하고 답한다

- 상단 기본 정보는 작품/화자와 현재 장면으로 제한한다. 상세 단계·팀 정보는 펼쳐 볼 수 있게 검토한다.
- 신규 작품의 예: **미션 1/3 · 흔들리는 바람섬** 또는 **장면 1/3 · 수상한 중고 거래**.
- 현재 장면 표시는 사용자가 ‘다음 장면’으로 이동할 때 변경한다. 응답 직후에는 현재 장면에 ‘완료’를 표시한다. 다음 장면을 현재 장면처럼 강조하지 않는다. 완료 개수는 별도로 일관되게 표현한다.
- 푸르마: **개강 · 체험 1/2턴**. 전체 12턴은 소개의 전체 스토리 정보로 구분하고 현재 시연의 분모와 혼합하지 않는다.
- 장면 제목·단계 번호를 타임라인과 상황 카드에서 반복하지 않는다. 사건 맥락은 첫 메시지 앞에 한 번 표시한다.
- 입력 안내: **선택하거나 직접 답해 보세요.**
- 입력 placeholder: **직접 답하기…**
- 전송 버튼의 접근 가능한 이름은 **전송**으로 통일한다. 아이콘·표시 형태는 레이아웃 설계에서 정한다.
- 응답 뒤 버튼: **다음 장면** / 마지막에는 **결과 예시 보기**.
- 구름섬은 메시지의 실제 화자와 심벌을 연결한다. 팀 전체 인물명 띠를 작은 글자로 상시 반복하지 않는다.
- 냉장고의 명패·표정, 푸르마 감정 PNG와 코믹 리액션은 유지한다. 리액션은 최신 응답의 중요한 순간에만 강조한다.
- 선택지에서 다음 버튼으로 바뀔 때 메시지가 과도하게 이동하지 않도록 위치·스크롤을 검토한다. 큰 빈 입력 공간을 항상 남기는 방법으로 해결하지 않는다.

### 결과: 결과를 읽고 다음 행동을 선택한다

- 공통 순서: 샘플 표시 → 캐릭터 → 결과명 → 짧은 설명 → 행동 영역.
- 일반적인 ‘오늘의 이야기, 한 장’, 영어 장식 제목과 캐릭터 캡션은 핵심 결과명보다 작게 하거나 생략한다.
- **주요 버튼 제안: 다른 작품 보기.** 현재 세 작품을 탐색하는 프로토타입의 목적을 따른 제안이며 사용자 확인 전이다.
- 보조 버튼: **다시 체험하기**, **작품 링크 공유**. 공유 기능은 유지하며 결과 이미지/개인 결과를 공유하는 기능처럼 표시하지 않는다.
- 푸르마의 **앨범 보기**는 전용 보조 행동으로 유지한다. 앨범·노트·대화로 돌아가는 기능을 삭제하지 않는다.
- 결과 화면은 자연스러운 페이지 스크롤을 우선 검토한다. 카드 전체를 작은 내부 영역에 넣기 위해 캐릭터를 과도하게 축소하지 않는다.

| 작품 | 결과명 | 설명 초안 |
|---|---|---|
| 푸르마 | 종강 생존 푸르마 | 선배와 함께라서 무사히 버틴 한 학기. 기존 기획 후보의 졸업 카드 샘플로 유지한다. |
| 냉장고 회장님 | 회장님과 한 식구 | 내일의 도시락을 지켜 줄 동거인이 생겼다. |
| 구름섬 | 마음을 잇는 구조대원, 나나 | 동료의 마음을 살피고 함께 나아가는 대원. |

구름섬 고정 샘플에는 ‘나를 닮은 대원은?’처럼 실제 분석 결과로 받아들일 수 있는 제목을 사용하지 않는다. 실제 매칭이 준비되면 별도 검토한다. 푸르마 샘플은 2턴 체험으로 한 학기 전체를 완료·판정했다는 뜻이 아니다.

## 4. Mock 고지 기준

정보를 숨기지 않고 반복 위치를 정리한다.

| 위치 | 표시 |
|---|---|
| 홈 | ‘시연용 콘텐츠’ 배지와 ‘정해진 대사를 사용하는 체험입니다.’라는 짧은 설명 |
| 작품 소개·체험 시작 전 | ‘실제 AI는 연결되어 있지 않으며, 직접 입력에도 정해진 대사로 답해요. 진행은 새로고침하면 초기화돼요.’ |
| 작품 체험 중 | 일관된 작은 ‘시연 모드’ 표시. 세부 설명은 접근 가능한 안내에서 다시 확인 가능하게 설계 |
| 결과 카드 | ‘결과 예시’ 배지와 ‘선택·발화를 분석한 결과가 아닌 고정 샘플입니다.’ 안내 한 곳. 푸르마는 ‘실제 획득·엔딩 판정이 아닌 디자인 샘플입니다.’ |
| 공유 | ‘작품 링크 공유’ 명칭 유지. 호칭·대화·결과를 공유 URL에 넣지 않음 |

오류 안내와 재시도, 입력 검증, 개인정보 관련 필수 안내는 장식 문구와 구분한다. ‘불필요한 문구 축약’을 이유로 기능상 필요한 설명을 일괄 삭제하지 않는다.

## 5. 디자인 규칙의 경계

- 공통: 정보 순서, 버튼 위계·상태, 기본 글자·여백, 입력 방식, 진행 상태 의미, 탐색·뒤로 가기.
- 작품별: 승인된 색·원화·제목 서체·질감·명패·하늘섬·리액션 표현.
- Figma 검토 대상: 홈 비율, 진입 통합 화면, 팀 소개, 채팅 입력/응답/오류 상태, 결과 카드와 행동 영역. 현재 Figma 산출물은 없다.
- 신규 캐릭터 원화·배포용 폰트는 기존과 같이 미제공이다. 이 문서의 승인만으로 외형이나 새 에셋을 확정하지 않는다.

## 6. 승인 후 2단계 범위

아래만 작은 변경 단위로 먼저 진행하고 로컬 화면으로 재확인한다.

1. 현재/완료 단계 표시의 모순과 푸르마 체험 분모 혼합을 수정한다.
2. 푸르마 완료 버튼의 간격·정렬을 정리한다.
3. 승인된 중복 문구·내부 분류·일반 버튼 명칭을 정리한다. Mock 고지의 상세보기 UI가 아직 없으면 기존 핵심 고지를 먼저 제거하지 않는다.
4. TypeScript/프로덕션 빌드와 변경 범위에 맞는 회귀 검증을 수행한다.

진입 화면 통합·홈/채팅/결과의 큰 레이아웃 변경·컴포넌트 재구성은 후속 단계다. 2단계에서 한꺼번에 변경하지 않는다.

## 7. 검토 요청

다음 두 방향을 포함한 1단계 안의 확인이 필요하다.

- 푸르마도 **작품 소개 → 캐릭터·호칭 → 첫 장면**으로 진입을 통합한다.
- 현재 프로토타입의 결과 화면은 **다른 작품 보기**를 주요 버튼으로, **공유·재체험**을 보조 버튼으로 둔다.

사용자 확인 전에는 이 안을 확정 기획이나 구현 완료로 기록하지 않는다.

## 2026-11-09 적용 결과

상태: **사용자의 백업 후 전체 적용 요청에 따라 코드 반영**. 위 ‘단계별 승인 대기’ 절차는 이번 요청으로 대체됐다. Figma 파일을 별도로 만들지 않고 로컬 구현·브라우저 검증으로 진행했다.

소개/호칭/대화 진입 통합, 홈 정보 위계, 채팅 헤더·현재/완료 표시, 결과 카드·공통 행동, Mock 고지 정리와 컴포넌트 분리를 적용했다. 실제 검증·제약과 백업은 `UX_REDESIGN_REVIEW.md`에 기록한다.
