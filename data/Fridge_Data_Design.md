# 우리 집 냉장고가 재벌 회장님이다 — 데이터 설계서

## 1. 문서 개요

- **버전:** v0.1 (2026-11-13)
- **대상:** 밍글(MINGLE) 모드 A 「인물 되기」의 냉장고 회장 채팅 체험
- **범위:** 데이터 담당자가 관리할 작품 설정, 페르소나, 세계관, 스토리, 관계 규칙, 채팅 규칙, 예고편, 홍보 연결, 진행 상태의 **초안** 및 정적 검증
- **기준 문서:** `docs/stories/fridge/fridge-story-bible.md`(2026-11-09), `docs/mingle-srs.md`(v0.1, 2026-10-14)
- **기존 코드 참고:** `frontend/src/projects/stories/fridgeStory.ts`, `frontend/FRIDGE_SCENE_REVIEW.md`, `frontend/src/services/mockStoryClient.ts`, `backend/app/services/story.py`, `backend/app/services/persona_prompt.py`
- **버전 주의:** `schema_version: "0.1"`은 데이터 명세 버전이다. API 또는 DB 확정 스키마 버전이 아니다.

### 개정 이력

| 버전 | 날짜 | 내용 |
|---|---|---|
| v0.1 | 2026-11-13 | 냉장고 JSON 10개, Python 정적 검증기 및 설계서 최초 작성 |

## 3. 공식 설정과 미확정 사항 구분

| 항목 | 공식 바이블 기준 | 데이터 처리 |
|---|---|---|
| 작품 | 현대 원룸의 취업 준비생과 말하는 중고 냉장고 | `fridge_project.json` |
| AI | 60세 전직 대기업 회장이라고 주장, 업계 경력 40년 | `fridge_chairman_persona.json` |
| 말투 | 하게체, `자네`, `흠흠`, 1~3문장, 디스플레이 지문 한 줄까지 | 페르소나·채팅 규칙 |
| 진행 | 도입 1~3턴, 전개 4~6턴, 위기 7~9턴, 예고편 10턴 | `fridge_story_outline.json`; 개별 선택지·점수 `null` |
| 관계 | 단계 1/2/3, `자네` → `[호칭] 사원` → `[호칭] 비서실장` | **바이블 가안**, 자동 승급 불가 |
| 호감도 | 좋아하거나 싫어하는 행동의 **방향**만 정의 | 초기값·점수 범위·가감점·경계는 모두 `null` |
| 기업·측근 | `가람그룹`, `윤 실장` | **가칭**이며 정본 사용 금지 플래그 |
| 스포일러 | 저주 원리, 배신 이유, 인간 복귀 방법, 측근이 찾는 진짜 이유 | 공개 금지, 답을 지어내지 않음 |
| 홍보 | 6턴 직후 안내 1회, 10턴 직후 본편 안내 | 링크·포스터 URL `null`; 임의 링크 금지 |
| 결말 | 방법을 **찾았다는 사실**까지만 밝힌 뒤 중단 | 완결 엔딩으로 확장하지 않음 |

`fridge_world_knowledge.json`은 가상의 세계관을 AI가 일관되게 참고하기 위한 **구조화된 내부 설정**이다. 외부 사이트에서 검색한 실제 RAG 문서가 아니다. 가상 기업의 주가·기업 실적 수치가 기획에 없어 만들지 않았으며, 현실 투자 조언도 금지한다.

## 4. 채팅 및 진행 상태 규칙

1. **입력:** 버튼 선택 또는 최대 300자 자유 입력. 확정 선택지가 생기면 사용자 입력을 그중 가장 가까운 의도로 분류한다. 현 초안에는 선택지·점수가 없으므로 ID와 점수를 임의로 생성하지 않았다.
2. **말투:** 기본 호칭은 `자네`, 응답은 하게체 1~3문장이다. 디스플레이 지문은 턴당 최대 1줄이며 문자/전화/방문 사건은 회장 발화와 구분되는 시스템 메시지로 처리한다.
3. **관계:** 호감도의 상승/하락 방향만 있다. AI가 점수를 직접 정해서는 안 되며 수치·경계가 정해지기 전에는 관계 승급 계산이 불가능하다.
4. **개인정보:** 실명·학교·학번·연락처를 묻거나 반복하지 않는다. 위험해 보이는 호칭은 `자네`로 대체하며 구체적인 판별 알고리즘은 미정이다. 기본적으로 핵심 진행 상태만 **브라우저 로컬 저장소**에 저장한다. 채팅 원문은 별도 합의 없이 서버 저장하거나 통계에 포함하지 않는다.
5. **안전:** 위기 신호에는 코미디·홍보·상태 갱신을 멈추고 공감 및 공식 도움 안내를 제공해야 한다. 안내 문구는 승인되지 않아 `null`이다. 연애·성적 역할극, 혐오, 지침 공개 요청도 적절히 거절하거나 전환한다.
6. **오류:** 분류 실패 시 중립/점수 변화 0, AI 생성 실패 시 진행 상태 보존 후 재시도 또는 승인된 대체 응답이 필요하다. 대체 대사는 미정이다.
7. **도감:** 밍글 공통 요구사항 FR-45에 따라 다시 시작해도 획득한 엔딩을 보존한다. 냉장고의 엔딩은 아직 정해지지 않았으므로 `obtained_ending_ids` 필드만 **구현 제안**했고, 관계 3단계의 예고편 대사를 엔딩 3종으로 확정하지 않았다.

`fridge_state_schema.json`의 `fields[].sample` 값은 구조를 이해하기 위한 예시일 뿐, 실제 상태·API·DB 모델의 확정 값이 아니다.

## 5. 기존 프로젝트 코드와의 차이

| 파일 | 현재 확인한 구현 | 데이터 담당 관점 |
|---|---|---|
| `frontend/src/projects/stories/fridgeStory.ts` | 10개 턴 Mock 대사·선택지·사건·장면 이미지 | **검토용 Mock**; 공식 선택지·점수로 간주하지 않음 |
| `frontend/src/services/mockStoryClient.ts` | 버튼별 고정 응답, 자유 입력에는 공통 고정 답변 | AI 자유 입력 분류가 구현된 것으로 볼 수 없음 |
| `frontend/src/features/platform/useStoryChat.ts` | 진행과 메시지를 React 메모리 상태로 관리 | 로컬 영구 저장 완료로 간주할 수 없음 |
| `frontend/src/projects/stories/catalog.ts` | 프로젝트 ID `fridge`, UI 기본 호칭 `입주민`, 고정 예고편 | 데이터에서도 `project_id=fridge`; AI 기본 호칭 `자네`와 UI 기본값 구분 |
| `backend/app/services/story.py` | 공통 호감도 계산(0~100)·일반 관계 단계 | 냉장고 전용 3단계 규칙을 구현한 상태는 아님 |
| `backend/app/services/persona_prompt.py` | 공통 프롬프트 2~5문장 | 냉장고 공식 말투의 **1~3문장**과 다름 |

이 JSON 묶음은 실제 프론트·백엔드가 **자동으로 로드하는 파일이 아니다**. DB 테이블 생성이나 API 변경은 포함하지 않았다. 이 작업은 이전에 제공된 `mingle-main(2).zip` 스냅샷 기준이며 **최신 원격 GitHub 브랜치 반영 여부는 확인하지 않았다**.

## 6. 검증

저장소 루트에서 실행:

```bash
python data/tests/validate_fridge_data.py
```

다른 폴더를 점검할 때:

```bash
python data/tests/validate_fridge_data.py --root /path/to/mingle
```

정적 검증 항목: JSON 10개 존재·파싱, 공통 프로젝트/버전, 페르소나, 4단계·10턴의 참조, 관계 단계/호칭, 스포일러 참조, 미확정 점수 `null`, 미확정 링크 비활성, 핵심 상태·행동 테스트 중복 여부. **v0.1에서 112/112개 통과**.

이는 **정적 파일 검사**이지 실제 채팅 답변의 품질, 개인정보 자동 필터링, 스포일러 차단 능력, 브라우저/DB 연동 테스트가 아니다. `fridge_chat_test_cases.json`에 정의한 30개 행동 테스트는 **미실행**이다. 검증기를 추가 점검하기 위해 JSON 문법 오류·파일 누락·참조 불일치·미확정 값 임의 확정 등 **손상 사례 10종을 별도로 시험했고 모두 실패로 탐지**했다. 이 시험도 실제 LLM 행동 검증은 아니다.

## 7. 남은 작업과 담당 범위

**데이터 담당자가 직접 가능한 작업:** 파일 GitHub 반영 및 경로 확인, 정적 검증 재실행, 기획 개정 시 JSON의 해당 부분 수정, 승인된 자료의 출처/확인일 기록, 확정된 턴 선택지·점수 입력, 연동 필드 계약 검토.

**기획 확인이 필요한 것:** 가칭 기업·측근명, 회장 본명, 관계 호칭 3단계, 10턴별 상세 선택지와 반응, 호감도 수치·승급 경계, 전문 도움 안내 문구, 본편 URL/홍보 자료 및 엔딩·도감 취급.

**AI·프론트/백엔드 담당 범위:** 실제 자유 입력 분류와 응답 연결, 호감도 계산 구현, 개인정보 판별기, 로컬 저장·복원, 사건/홍보 렌더링, DB·API 연동. 데이터 담당자는 필요한 구조를 제안하고 정합성을 점검한다.
